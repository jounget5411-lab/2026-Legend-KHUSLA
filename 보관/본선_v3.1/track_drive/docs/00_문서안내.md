# 00. 문서 안내 — 무엇부터 읽으면 되나

국민대 자율주행 본선 실차(1/10 Xycar) 코드 `track_drive` 의 전체 사용설명서다. 2026-07-31 카메라 캘리브레이션 완료 시점의 코드를 기준으로 썼다. 코드를 처음 보는 사람이 "이 기능은 어느 파일 어느 함수구나"까지 연결할 수 있게 하는 것이 목적이다.

문서는 8편이고 전부 따로 읽어도 되게 만들었다. 다만 **01 전체그림은 먼저 읽는 게 좋다** — 나머지 문서가 전부 거기서 갈라져 나온다.

---

## 1. 목적별 읽는 순서

무엇을 하려는지에 따라 필요한 문서가 다르다.

| 지금 하려는 일 | 읽을 순서 |
|---|---|
| 이 프로젝트가 뭔지 알고 싶다 | **01** 하나면 된다 |
| 차를 직접 굴려야 한다 | **06** → 01 → 04 |
| 카메라를 다시 맞춰야 한다 | **07** → 05의 2장(camera.yaml) |
| 주행이 이상해서 값을 만져야 한다 | **03**의 9장(튜닝 표) → 05의 3장(tuning.yaml) |
| 코드를 고쳐야 한다 | 01 → 해당 영역(02 인지 / 03 판단 / 04 제어) |
| 왜 이렇게 느린지 알고 싶다 | **08** |
| 팀원에게 인수인계한다 | 00 → 01 → 06 순으로 같이 읽기 |

  │      path_planner_node           │   ← 판단

  └───────────────┬──────────────────┘

          ┌───────────────┐
          │  motion_node  │              ← 움직인다 (제어)

## 4. ★ 지금 알려진 미해결 사항

문서를 쓰면서 코드를 정독하다 발견한 것들이다. 전부 실제 코드를 열어 확인했다.

### 4.1 안전 관련

| 항목 | 내용 | 위치 |
|---|---|---|
| 데드맨 가드가 꺼져 있다 | `deadman_enable` 기본값이 `False` 라, 명령이 끊겨도 자동 정지하는 안전장치가 동작하지 않는다 | `ros1_docker/vesc_relay.py:34` |

### 4.2 미구현 / 죽은 코드

| 항목 | 내용 | 위치 |
|---|---|---|
| 추월 미구현 | `OvertakeStub.update()` 가 항상 `None` 을 반환한다. 인터페이스만 있고 알맹이가 없다 | `path_planner_node.py:102-104` |
| 흰선 배선이 죽어 있다 | `yolo_node` 는 MID(z=8)만 발행하는데 `lane_planner` 는 `WHITE_CLS_IDS={6,2}` 로 흰선을 걸러낸다 → 항상 빈 배열. `plan()` 이 흰선을 안 쓰므로 동작상 문제는 없지만 배선이 끊겨 있다 | `yolo_node.py:329`, `lane_planner.py:41-43` |
| `_busy` 는 아무 일도 안 한다 | `rclpy.spin_once` 가 단일 스레드라 콜백 재진입이 구조적으로 불가능하다. 실측에서 `busy_drop=0`. 실제 프레임 드랍은 QoS `depth=1` 이 한다 | `yolo_node.py:158` |
| LEFT 디바운스가 디바운스가 아니다 | `_sc_left_hits` 가 인지 프레임당이 아니라 planner 틱당(20Hz) 증가하고 `_obj_cls` 는 캐시라, LEFT 가 든 프레임 1장이면 100ms 만에 확정된다 | `path_planner_node.py:787-791` |

### 4.3 미검증 값 — ★ 대회 전 반드시 확인

| 항목 | 내용 | 위치 |
|---|---|---|
| **`stop_v_threshold: 312.0`** | 시뮬 480p 에서 튜닝된 값이고 실차 재튜닝 이력이 0회다. **이게 틀리면 인지가 몇 Hz 든 정지선에서 잘못된 위치에 선다.** 성능 개선보다 우선순위가 높다 | `tuning.yaml:83` |
| `cross_v_threshold: 278.0` | 위와 동일 | `tuning.yaml:84` |
| `track_width: 4.4` | 예선 트랙 폭. 본선 코스에서 재측정 필요 | `tuning.yaml` |
| `stop_heading_rel`, `stop_block_heading_rel`, `sc_turn_target_deg` | 코스 형상 의존값. "코스 실측 예정" 상태 | `path_planner_node.py:162, 178, 180` |
| `cone_single_bias = 0.268` | 예선 콘 코스가 **시계방향 루프**라는 전제로 박혀 있다. 본선 코스 회전 방향이 반대면 부호를 뒤집어야 하는데 자동 판별이 없다 | `path_planner_node.py:977` |
| `SEG_CHILD_DASH = 2` | 클래스 id 가 미검증이다. 코드 주석에도 "재확인 필요"로 남아 있다 | `yolo_node.py:69` |

### 4.5 성능

| 항목 | 내용 |
|---|---|
| **653ms 카메라 지연** | `header.stamp` 대비 도착 지연이 653ms(sd 3.3ms)다. 타임스탬프 버그인지 진짜 버퍼링인지 아직 판별 안 됨. 진짜라면 인지 최적화보다 7배 큰 문제다 (08 문서 5장) |

## 7. 이 문서 묶음의 한계

정직하게 적는다.

- **주행 검증이 안 된 상태에서 쓴 문서다.** 카메라 캘리브는 2026-07-31 에 끝났지만 그 값으로 실제 트랙을 달려본 적이 없다. 4.3절의 미검증 값들이 그대로 남아 있다.
- **08 문서의 성능 수치는 "검출 대상이 없는 장면"에서 측정됐다.** 실제 주행에서는 마스크 후처리가 얹혀 더 느리다.
- 코드 인용의 줄번호는 2026-07-31 기준이다. 코드를 고치면 어긋난다.
- 문서 작성 후 교차검증에서 사실오류 66건을 잡아 고쳤지만, 남아 있을 수 있다. **문서와 코드가 다르면 코드가 맞다.**
